# 受控导入与结果导出

## 当前范围

本任务在 Windows/WSL 仅新增代码、工具安装包、公开哈希元数据、良性 PE 和结构化结果。用户提供了主机上已经存在的加密归档；本任务没有在宿主机下载、解包、运行或另存该归档中的样本。归档直接进入已验证隔离的专用 VM，客户机也只做静态扫描。

2026-10-03 已验证 VMware Tools 非特权账户在完全离线状态下的无害文件往返、良性 PE 静态扫描、真实归档静态读取及只导出结构化结果。仍须每次用 `Test-OfflineGuestOps.ps1` 验证，不能因为 Tools 显示 running 就推定隔离通过。

## 良性开发与更新

1. 确认专用 VM 中没有真实样本；若曾导入，先关机恢复经过验证的干净基线。确认 `vmcli Power query` 为 off，而非 suspended。
2. 工具/签名准备可使用 NAT；只在这一阶段执行 freshclam。保存 `sigtool --info` 的版本、签名数、校验结果和数据库日期，关闭 freshclam 后冻结版本。
3. 关机切换 Host-only，启动后确认只有 vmnet1 链路路由、没有默认路由。SSH 用专用密钥和固定 known_hosts 核对客户机，不自动接受新主机密钥。
4. 导入预先核验的良性文件及清单。清单保存 SHA-256、出处、签名者、标签依据和测试划分；在客户机再次核对内容 SHA-256 和 PE 完整性，文件不执行。
5. clamd 重启后要确认 VERSION 探针成功、YARA 规则已加载，再开始完整实验。加载期间的 unavailable 与扫描超时分别保留，不能计为阴性或用热缓存重扫覆盖。
6. 只导出 JSON 结果和清单；良性样本不提交 Git。记录规则/数据库版本、完整命令、缓存层、硬件、失败项和原始结果校验值。

## 离线管理验证

1. 真正关机，执行 `Manage-VM.ps1 -Action Offline` 和 `CheckOffline`；启动后确认无客户机 IP、共享目录列表为空，VMX 禁用全部 NIC、HGFS、剪贴板、拖放、USB 和 VMCI。
2. 用控制台截图核对本次 boot 的客户机报告。客户机只允许 loopback、无 IPv4/IPv6 路由、无 HGFS 挂载。查询工具缺失或一般查询失败必须拒绝；HGFS 的明确关闭诊断需与主机关闭设置一致。
3. 执行 `Test-OfflineGuestOps.ps1`。它导入新生成的无害文本，客户机重新计算 SHA-256 并重新运行隔离检查，经 Tools 导出两个文本结果。摘要必须相同，检查必须 PASS；不开放网络、共享或剪贴板来使操作通过。
4. 保存导入摘要、导出摘要、检查报告、boot ID、VMX 状态、Tools 状态和截图。未完成这些证据时，真实样本步骤不执行。

## 用户已有归档的静态分析（已执行）

1. 在良性 Host-only 准备阶段，将可信项目源码打包为 `static-guest-tools.tar.gz` 送到 `/home/ubuntu`，运行 `Install-StaticTools.sh`，安装 root 所有的只读扫描代码。准备专用非特权账户；真正关机，切换 Offline 并建立经过恢复验证的干净快照。
2. `Analyze-OfflineArchive.ps1 -SourceArchive <用户已有归档> -ArchivePassword <SecureString>` 先重复离线 VMX/客户机检查与无害往返。失败即停止；不临时恢复 SSH、网卡、共享、剪贴板或拖放。
3. 宿主机只对外层 ZIP 计算摘要，通过 Tools 直接复制到新建的客户机私人目录。程序只接受已有 ZIP，最大 128 MiB；不在宿主机读取归档成员、暂存副本或下载真实样本。
4. 客户机重新核对归档 SHA-256、隔离 PASS 和 clamd VERSION。非 root 程序递归读取 ZIP 内存字节，最多 8 层、2000 项（包括目录）、累计 512 MiB，单项最多 64 MiB；拒绝危险路径和符号链接。修订版在 ZipFile 分配目录对象前核对全部目录头与数量，拒绝 ZIP64/多盘归档；预算耗尽记录跳过。不会写出或执行任何叶文件，ZIP 兼容 EXE 仍按完整文件扫描，不递归其内部资源。错误密码/不支持的加密/损坏成员记录为 `read_or_password_error`，不猜测密码。
5. 扫描进程关闭 core dump，地址空间上限 1.5 GiB、CPU 1800 秒、输出文件上限 2 MiB。主机导出固定位置的 JSON/摘要，核对大小、SHA-256、归档身份、完成标志及字段白名单；状态、数值、证据长度均有约束，拒绝额外载荷字段。不导出归档、原始叶文件或样本字节。
6. 只用样本 SHA-256 关联冻结的独立标签参考；它不能进入检测数据库。保存报告后关机恢复干净基线，核对新的 boot ID 和隔离 PASS，才可再进入良性准备阶段。恢复不宣称物理擦除宿主机虚拟盘块；虚拟盘不在宿主机挂载。

本批标签参考来自用户指定的 apicall 已保存 VirusTotal 报告：排除被测 ClamAV/ReversingLabs 后，至少 5 个厂商恶意判定才记 `malicious_proxy`（实际最低 24 个）。2026-10-10 修订标签：RuntimeBroker 为 `unknown`，排除良性/恶意分母；历史签名和零命中不能证明良性。旧批次原标签仅用于追溯。原始来源、许可链和独立人工真值未核实，不能把这些代理标签包装成正式数据集验收。

## 后续独立数据集仍需落实的步骤

- 样本必须来自许可及标签可核查的来源，先冻结实验协议和样本批次，核对用户对大规模下载的授权。不能把测试 SHA-256 加入参考库后报告未知样本检出率。
- 新来源需要让原始字节直接进入隔离 VM 存储；当前 Tools 通道只处理用户提供的已有归档，不提供在宿主机下载真实样本的许可。不能用宿主机下载后复制、Windows/WSL 解包、共享目录或临时 SSH 绕过约束。
- 后续可评估用户提供的专用样本虚拟磁盘/离线介质，保持宿主机不挂载、不解包，挂接前确认来源、文件清单和只读策略；具体导入操作及隔离边界需验证后执行。
- 样本区只允许非特权扫描账户访问，扫描程序与配置由管理员维护；不从样本目录执行程序。资源限制错误、超时和解析失败单列为未完成。
- 导出通道只接收约定结构的 JSON：哈希、引擎状态、规则/签名版本、证据和耗时，标签在主机关联独立参考。客户机先生成独立报告，宿主机导出后核验结构、大小和摘要；不导出样本、归档或可执行文件。`static_archive.py --validate-export` 已部署并实测。
- 一批实验结束后软关机，恢复干净基线，再独立核验新 boot 的隔离状态。含真实样本的磁盘不在宿主机挂载，残留处理单独授权。

隔离或来源通道无法验证时，仅暂停真实样本导入与检出实验；良性测试、工具诊断和模型研究准备继续。
