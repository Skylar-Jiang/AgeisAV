# 课程评测证据盘点与可复现历史汇总

本次完成已有记录的去重、标签分层和单引擎/融合重汇总，没有新增扫描或训练。
当前有完整的多引擎工程证据和可复现的开发实验，但尚未完成“独立原始 PE 恶意10万+良性10万”的课程评测目标。
严格独立验证准入、最终集准入和独立人审均为0。未观察文件不能自动计入最终集。

机器结果见[汇总 JSON](../benchmarks/course_evaluation_20261022.json)，
复现入口为[course_evaluation_summary.py](../../experiments/course_evaluation_summary.py)。
脚本仅打开明确列出的既有 JSON；不打开原始 PE、特征/预测数组，不访问网络或操作 VM。
结果中的输入摘要绑定历史来源；不公开样本 SHA、原始文件路径或私有标签包内容。

## R7去重与标签口径

原始成功主报告285行，成功R4补充报告13行；两者合并后298个不同SHA，重复0。
历史`paired-summary`已经包含补充13行，不能再把它与主/补充计数相加。
298个身份与观察账本完全一致，且与显式受保护的106个身份不相交。
本次逐引擎阳性和融合阳性均复现历史汇总。

标签分成286个`presumed_benign_operational`、10个`malicious_operational_proxy`和2个unknown。
10包括7个旧技术案例和3个新增自动高可信案例，仍然缺独立人审和严格准入。
两项技术/提供者家族争议为ZionSiphon/RustyStealer、DarkCloud/a310Logger，保持unknown。
unknown中的1个告警、1个未告警均保留；两者不进入下表的TP/FP/Recall/Precision分母。
因此“全部12个技术案例10次阳性”和“排除unknown后10个操作性案例9次阳性”同时成立。
不能把10个操作性案例改写为10个独立真值恶意文件。

`alert`明确表示报告`suspicious`或`malicious`。历史298份报告中15个`suspicious`、283个`undetermined`，
**没有一个`malicious`最终裁决**；ClamAV的4次匹配也产生`suspicious`证据。
`undetermined`在二值“是否告警”描述中为未告警，不能读作已判定安全。

## 历史健康ClamAV时代的成本

这批Linux测量使用SHA/模糊参考`279d0104511d2850`，YARA-X1.20.0/`55ccec8463af1166`，
ClamAV1.5.4/库28148，LightGBM4.6.0/EMBER2024v3，冻结registry与`evidence-or-v1`。
通用阈值0.5，Win64研究阈值0.9831222501035356。
它与当前Windows ClamAV不可用时的性能测量分开，不能补成当前“健康五引擎”结果。
旧面板的资产身份及日期分别绑定在JSON和原报告中；用户归档旧规则仅2条，不与R7的246条直接比较效果。
