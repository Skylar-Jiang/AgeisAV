# YARA 编译结果复用候选：2026-11-01

本轮保留稳定源码的默认规则编译路径，新增显式、摘要固定的编译结果加载接口及隔离研究 Worker。
没有修改生产模型、阈值、规则、融合、0.2.0 或 0.2.1rc1 ZIP，也未访问 VM 或原始恶意 PE。
工作区和远端公开分支核对后，承接 2026-10-23 已验证基线；没有发现可复用的 10-29 新提交或实验产物。

## 改动与信任边界

已有 profiling 指出一次性 Worker 每次构建均重新编译 246 条 YARA-X 规则。本轮保持一次性进程、Job 限制、
认证、队列与 SQLite 不变，只比较源码编译与同一规则集的序列化结果加载。
[官方 Python API](https://virustotal.github.io/yara-x/docs/api/python/)提供 `serialize_into` / `deserialize_from`。
现有固定运行时为 yara-x 1.20.0；官方[反序列化公告](https://github.com/VirusTotal/yara-x/security/advisories/GHSA-2jx3-ff3v-j7jj)
列出的旧版本问题已在 1.19.0 修复。本候选仍只接受受信构建结果，不接收上传的编译规则。

`load_yara_engine` 的默认调用行为不变。显式候选必须同时给出文件与**构建时记录、保存在文件外部的 SHA256**。
读取最多 8 MiB，先核验完整字节摘要，再核验 schema、完整规则及元数据摘要、安装的 YARA-X 精确版本，
最后反序列化已经核验的内存字节。规则 ID、来源和元数据验证仍执行；不会悄悄回退或生成 no_match。
当前 bundle 为 1,503,918 B；版本和报告的规则身份保持原值，逐对比较不忽略裁决、证据或特征摘要。

生成器拒绝覆盖已有候选。候选入口在读取 PE、导入解析器和加载 bundle 前执行现有 `contain_worker()`；
调用者仍为 `ProcessScanner`，沿用 16 MiB 输入、2 MiB 报告、2 GiB Job 和终止清理机制。
没有增加常驻 Worker、跨任务检测缓存或新的服务端上传接口。

## 配对 HTTP 结果

两臂都使用同一个现有原生 SSDeep、冻结通用 ML、规则和控制器，仅改变 YARA 加载方式。
真实认证回环 HTTP 从客户端 base64/JSON 编码至终态响应计时，包括上传、排队、进程启动、解析、
外置 ML、报告和 SQLite。小文件为安装来源 notepad，大文件为 Python DLL；批次四项含一个重复项。
每场景五轮交替，两种 ClamAV 状态分开，共 30 对任务。不是 30 个独立样本或跨机器结论。

| ClamAV | 场景 | 编译 P50 / P95（秒） | bundle P50 / P95（秒） | 编译 → bundle 吞吐（提交项/秒） |
| --- | --- | ---: | ---: | ---: |
| 健康 | 小文件 | 2.656 / 3.106 | 1.925 / 2.108 | 0.3662 → 0.5153 |
| 健康 | 大文件 | 8.332 / 9.916 | 6.876 / 7.041 | 0.1229 → 0.1455 |
| 健康 | 混合批次 | 8.749 / 15.428 | 6.060 / 6.822 | 0.4017 → 0.6507 |
| 不可用/弃权 | 小文件 | 2.787 / 6.011 | 2.028 / 2.935 | 0.2913 → 0.4548 |
| 不可用/弃权 | 大文件 | 8.545 / 9.576 | 7.177 / 13.983 | 0.1174 → 0.1048 |
| 不可用/弃权 | 混合批次 | 9.094 / 10.883 | 6.444 / 8.515 | 0.4247 → 0.5845 |

健康场景小文件、大文件、批次 P50 分别降低 27.5%、17.5%、30.7%。不可用场景小文件和批次分别降低
27.2%、29.1%；大文件虽然中位数降低 16.0%，P95 升高且平均吞吐下降 10.7%，因此不推广为全场景收益。
候选两轮大文件总耗时为 12.876 / 13.983 秒，ML 特征提取为 10.023 / 10.366 秒；同轮基线特征提取
为 4.763 / 4.887 秒，YARA 扫描本身约 0.1 秒。阶段记录指出延迟发生的位置，**不能证明其成因**。
全部慢轮保留，没有删点、混合 ClamAV 状态或把不同优化的百分比相乘。

P95 是五次观察的最大值，不是总体尾延迟保证；首次执行、CPU 调度、系统负载和文件缓存均可能影响结果。
两臂 API 实际取消、后续扫描恢复、服务关闭和 SQLite 重开一致性全部通过。

## 检测一致性、资源与失败

另用 11 个已观察良性开发控制，覆盖 Win32/Win64、EXE/DLL、托管 PE、较大系统文件及 SQLite、7-Zip。
两个 ClamAV 状态重复同一批文件，共 22 对完整报告一致；只规范化三个计时字段。
原有两个 ML 告警均保留，两个版本均为 2 suspicious / 9 undetermined；没有把 undetermined 称为安全。
SHA256、模糊哈希、YARA 均 11 no_match；健康 ClamAV 为 11 no_match，不可用时为 11 unavailable。
模型为 2 matched / 9 no_match。这些控制按已观察案例选择，不能计算总体误报率。

| ClamAV | 编译 / bundle 采样进程树 RSS 最大值（MiB） | 编译 / bundle 采样累计 CPU（秒） |
| --- | ---: | ---: |
| 健康 | 402.41 / 385.05 | 48.719 / 36.672 |
| 不可用 | 401.73 / 384.32 | 48.063 / 40.047 |

资源比较是 11 个异质文件各一轮的辅助观察，20 ms 采样可能漏峰，共享页可能重复计算；不包含 clamd，
不将不同时间的峰值相加。健康场景自有 clamd 最低主机可用 RAM 为 4,999,782,400 B，未触发 2 GiB
余量守卫，结束后确认退出；原签名库字节不变。版本为 1.5.4 / daily28161，属于冻结库比较而非最新库覆盖率。

每个状态均用无害夹具在**实际加载本 bundle 后**验证取消、超时、崩溃和 256 MiB Job 拒绝 512 MiB 申请，
四项清理及后续真实扫描恢复通过。阳性规则夹具、摘要篡改、来源/元数据变化、运行时不符、超限、
配置不完整和拒绝覆盖也通过。夹具不会执行扫描目标 PE，不代表恶意家族检出率。

本轮没有训练或读取 40,000 行开发验证/独立最终特征，没有新增恶意检出率、FPR 或低 FPR Recall 结论。
已有准确率研究状态及课程证据继续以原记录为准；原有误报与漏检问题并未由此解决。

## 复现与交付状态

```powershell
.venv\Scripts\python.exe -B -m experiments.yara_bundle --output artifacts\new-rules.bundle
# 将构建时打印的 SHA256 存入受信配置；下面使用该固定值，而非从待加载文件自行信任摘要。
.venv\Scripts\python.exe -B -m experiments.compare_task_latency `
  --baseline-root . --candidate-root . `
  --candidate-yara-bundle artifacts\new-rules.bundle --candidate-yara-sha256 <构建时记录的SHA256> `
  --shared-native-root artifacts\windows-delivery-20261022-rc1\AegisAV-0.2.1rc1-Windows-x64\app\native `
  --clam-state unavailable --rounds 5 --output artifacts\new-http-result.json
```

健康状态使用既有受控 ClamAV sidecar，不在配对期间更新签名。静态/资源/故障复现工具为
`experiments.validate_yara_bundle`；它要求显式 bundle、摘要、原生目录、实际 ClamAV 状态和新输出目录。
私有完整日志、报告、协议、bundle、自有 daemon 编排、资产摘要及测量源码保留在 `artifacts/yara-bundle-20261101`。
[公开聚合 JSON](../benchmarks/yara_bundle_20261101.json)不含样本身份、凭据或原始 PE。

只读审查发现测速 CLI 在组合候选选项时可能忽略 SSDeep 选择；已增加互斥拒绝，并显式固定后端、
尊重指定源码快照。两个真实子进程回归先失败后通过。该问题不影响本次同源码/显式共享原生后端测量；
原始实测脚本与摘要单独保留，加载器和实际 Worker 函数未变，修正后的 CLI 另做真实 HTTP 冒烟。
复审无剩余阻断。完整后端 403 passed / 8 skipped，一个既有 AnyIO 弃用警告；ML 兼容检查 2 passed，
13 个第三方 Pyparsing 弃用警告。264 项受保护资产摘要一致。

当前结论：**保留为有价值的显式工程候选，不默认启用，不覆盖稳定包，也不改名发布正式 0.2.1**。
下一步优先针对大文件 ML 特征提取波动做受控比较，并在独立便携候选中绑定 bundle 构建摘要、完成首次运行及
不同目标机器验证。规则/数据/模型变更仍须独立检测证据，不能用本轮一致性替代泛化确认。
