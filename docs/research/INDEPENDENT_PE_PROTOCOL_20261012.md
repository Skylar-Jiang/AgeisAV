# 独立原始 PE 评测协议 v1（候选准备阶段）

当前没有通过本协议的独立最终 PE 数据集；不发布新的 Recall/FPR。
协议日期为 2026-10-12，制定时未运行新候选的检测器或查看模型分数。

## 来源与访问边界

- [MalwareBazaar 官方 API](https://bazaar.abuse.ch/api/)要求 Auth-Key。用户已授权现有账号，密钥由 Windows 当前用户 DPAPI 加密，位于仓库外的 `.codex/secrets/aegisav/`，目录 ACL 不继承。脚本不包含密钥。
- [官方 FAQ](https://bazaar.abuse.ch/faq/#api-limit)规定文件 API 每 IP 每日最多 2000 次下载；这不是本项目的采集目标，也不是元数据接口的公开每分钟配额。本项目先设更保守的元数据预算：串行、至少间隔 60 秒、每日最多 10 次预留尝试，遵守更长的 Retry-After，失败不自动重试。账号其他客户端也共享供应商限制。
- Windows 的 `Get-MalwareBazaarCandidates.ps1` 固定只请求 `get_recent/100` JSON，拒绝重定向和非 JSON，不支持 `get_file`、上传或评论。每次响应上限 8 MiB；原始元数据留在忽略的 artifacts，公开记录只含请求审计。HTTP 错误不输出请求对象或认证头。
- 原始恶意文件的下载/解密必须由新的受控导入流程完成：先确认离线分析 VM 的隔离，再建立专用取样暂存边界。**不得为直接下载而重新连接装有样本的分析 VM 网络，不经 Windows/WSL 落地 ZIP 或 PE**。现有 vmrun 离线传输能力不自动解决互联网到离线 VM 的可信导入问题。该流程未验证前只采集元数据。
- [BODMAS 作者页面](https://whyisyoung.github.io/BODMAS/)的原始文件需申请，未代用户联系。其旧时间段不适合直接证明对 EMBER2024 的向前时间泛化。
- [SOREL20M](https://github.com/sophos/SOREL-20M)公开的文件经过失活，且原始 SHA 与提供字节身份需区分；不恢复执行能力，也不把这些字节冒充完整原始 PE 的公平配对测试。[EMBER2024](https://github.com/FutureComputing4AI/EMBER2024)特征本身不能替代原始文件配对。
- 良性候选来自[微软 Sysinternals Suite](https://learn.microsoft.com/en-us/sysinternals/downloads/sysinternals-suite)，受[许可约束](https://learn.microsoft.com/en-us/sysinternals/license-faq)，原始 PE 不加入仓库或再分发。官方来源与有效签名只支持推定良性；合法双用途工具的类别单独审核。

## 纳入与划分

1. 只收录可溯源、字节 SHA 验证、静态可解析、范围明确的原始 PE。记录取得时间、来源首次出现时间、来源版本/响应摘要、标签证据、家族及文件类型。编译时间、签名时间、套件更新时间和取得时间不能冒充可信首次出现时间。
2. 元数据时间窗口预设为验证集 `2025-01-01 ≤ first_seen < 2026-01-01 UTC`，最终候选 `first_seen ≥ 2026-01-01 UTC`。它们是拟建新队列，不替代旧 EMBER 划分。时间证据必须独立于本项目扫描；首次出现时间也不证明此前从未传播。
3. 标签审核与被测引擎结果隔离。恶意需独立来源/人工静态证据；不能因为 MalwareBazaar 收录或 ClamAV 命中就直接作为最终真值。良性需官方取得与独立审核，签名有效/五引擎全阴性不足。PUP、双用途、来源冲突、RuntimeBroker 等不确定项单列，预先确定产品策略，不混入主二分类分母。
4. 排除所有已观察开发文件及旧模型拟合/验证/测试 SHA。当前本地 Win64 三分区可审计；通用模型全部训练成员和模糊摘要尚不完整，必须保留此限制。
5. SHA 全局去重。TLSH 距离 ≤40 或 SSDeep 相似度 ≥80 是预设的**泄漏筛查**条件，不是修改检测阈值。对候选、训练、已观察语料建立连通分量；与旧数据相连或跨验证/最终时间边界的整个分量隔离。另审查签名、版本、导入、家族/打包器关系，模糊摘要不等于完整语义独立性证明。
6. 暂定每个分区至少 20000 良性、2000 恶意，并报告家族、来源、时间和类型分布及有效独立簇数。这个目标不构成样本量充分性保证，置信区间和采样偏差必须报告。
7. 未达标签、时间、来源、完整训练排除和近重复审计条件的一律 quarantine。`independent_cohort.py` 的数量门槛不能独自签发最终资格，因此其 `ready_for_paired_final_evaluation` 恒为 false。

## 冻结与配对指标

- 旧权重、阈值、最终结果保持冻结。新实现 `chunked-histogram-v1` 只改变计数内存路径，模型分数语义不变。新阈值或融合策略必须使用新独立验证集，建立新 policy/model ID，不根据旧最终分数再调。
- 完成审核后先冻结清单、簇、标签、来源响应、划分和代码摘要。最终集在新策略冻结前封存；运行一次最终评测后标记 observed，不能再次充当新版未见最终集。
- 各引擎、默认通用模型、可选 Win64 范围策略和融合必须处理**同一字节 SHA**，记录每次状态、分数、阈值、资产版本、耗时、资源与缓存。官方哈希情报不得把待测 SHA 回填参考库；相似参考也必须在划分前冻结并排除泄漏。
- 报告 Recall、FPR、置信区间、每类弃权率；同时报告已完成决策的条件分母和全输入分母，保守 Recall 将弃权计作漏检。未知/读取失败/不适用不能静默丢弃或记成阴性。
- 固定低 FPR 目标为 1%/0.1%/0.01%，仅验证集选阈值，最终集报告实际 FPR 与相应 Recall，不能在最终 ROC 上寻找“最佳部署阈值”。零误报需给区间；样本量不足时不宣称满足低 FPR。
- 融合预先比较现有 OR、签名优先、模型与其他证据协同的解释性候选。开发归档 109/109 OR 只用于错误分析。模型互补增益、增加的 FP、弃权变化和额外扫描成本一并报告。
- 缓存关闭是准确率/首次扫描成本主实验；缓存冷热对照独立列出。性能按 EXE/DLL/托管/架构和大小分层，固定资源、并发、同一输入与运行顺序，记录系统和 clamd 内部缓存未清空的限制。
